MP-01

Multi-Cipher Console Program

IT129 · Information Assurance & Security· C# (.NET console)· Team· Cryptography
Discussion of the features

A menu-driven cryptography suite that implements several classic ciphers from scratch plus one cipher of the team's own design, all sitting on a small reusable console-UI framework. The framework (Menu / Choice) binds each menu item to a label, a key, and a delegate, which cleanly decouples the interface from the algorithms — new ciphers can be registered without touching the menu code.

  • Caesar cipher — alphabetic shift by a user-supplied integer, with encrypt/decrypt/info.
  • Vigenère cipher — keyword cipher that also prints the full Vigenère reference table.
  • XOR cipher — repeating-key bitwise XOR; ciphertext shown as hex, with hex-to-bytes parsing on decrypt.
  • Meguprazan cipher — the group's original cipher, with matching encrypt and decrypt routines.
  • Reusable menu engine — colored titles, descriptions, and per-item hotkeys drive the whole app.

MP-02

Python Cryptography Toolkit

IT190-4P · Cryptography· Python 3· Solo· Cryptography
Discussion of the features

Two-part cryptography coursework: a hand-written classic-cipher CLI, and a benchmark comparing modern production ciphers. The first part (Lab1.py) is a menu-driven Caesar + polyalphabetic cipher implemented from scratch over the full printable-ASCII range (codepoints 32–126, mod 95) — with input validation, negative-shift handling, and length checks. The second (FishTacos) moves to library-grade ciphers and measures them.

  • From-scratch ciphers — Caesar and polyalphabetic encryption across all printable ASCII, not just A–Z.
  • Salsa20 vs Blowfish benchmark — stream vs block (CBC, manual PKCS-style padding) via PyCryptodome, timed with perf_counter().
  • Test harnesses — several *Tests*.py suites, including an interactable one, plus sample data files.
  • Input validation — guards on shift range and message length before running.

MP-03

Marine Adventures — 2D Shooter

Object-Oriented Programming· C# · WinForms (.NET 4.7.2)· Team · 2023· GitHub ↗
Discussion of the features

A desktop 2D shooter built to exercise object-oriented game design: one class per game concept, real-time collision and spawning, power-ups, a boss enemy, and persistent high scores. Character and Environment act as shared base classes; Player, Enemy (with a Boss variant), Bullet, PowerUps and Obstacles extend the model.

  • Real-time gameplay — movement, shooting, collision detection and enemy spawning on a game loop.
  • Power-ups — Health, Speed and Attack pickups that modify the player mid-run.
  • Boss encounter — a distinct boss enemy initialized separately from regular waves.
  • Persistence — game state saved to gameSave.txt and high scores appended to highScores.txt.
  • Screen flow — main window, game window, end screen and high-score screen.

MP-04

Resort Management Database

Database design· SQL (T-SQL DDL)· Team· Schema design
Discussion of the features

A relational schema-design artifact for a resort-management system — a design-only deliverable (Statements.txt) rather than a runnable app. It demonstrates normalized modelling with primary keys, check constraints and referential relationships.

  • Departments — role as primary key with a CHECK constraint limiting roles to Accountant / Maintenance / Reception, plus salary range and qualifications.
  • Manager & Employees — an employee "managed-by" relationship modelled with foreign keys.
  • Constraints-first design — keys, checks and relationships expressed directly in CREATE TABLE DDL.

MP-05

Document Management System — “DocuSafe”

IT140P · Web systems & databases· PHP · MySQL· Solo· Web · CRUD
Discussion of the features

A database-backed web app for storing personal documents with expiry tracking, user authentication and full CRUD — including binary file storage. Users authenticate against a users table using password_verify() against bcrypt-hashed passwords; documents (with the file itself) live in a docusafe table as BLOBs. The project evolved from an earlier records-only lab prototype into the finished app.

  • Secure auth — bcrypt-hashed passwords and prepared statements throughout.
  • Binary file storage — multipart uploads inserted as BLOBs and streamed back on demand.
  • Expiry tracking — each document carries an expiry date alongside type and timestamps.
  • Full CRUD + search — add, edit, delete and search documents per authenticated user.

MP-08

Inventory Management App

Mobile application development· Xamarin.Android (C#) · PHP REST · MySQL· Team· Mobile
Discussion of the features

A native Android inventory app with user accounts, backed by a custom PHP REST API over MySQL. The codebase keeps a clean separation between UI and data: every feature pairs an Activity (screen) with a Handler (API call). Inventory is scoped per user (owner), and item types are populated from a bundled catalog.

  • Accounts — register and login flows against the REST API.
  • Full CRUD — add, update and delete items, plus search and sort.
  • Activity / Handler architecture — UI activities cleanly separated from API-call handlers.
  • Per-user data — an itemsTable scoped by owner, with types from an XML catalog (Clothing, Food, Technology, Other).

MP-09

IoT Monitoring & Control Dashboard

IT155P · IoT / full-stack· Next.js 16 · React 19 · Supabase · Wemos· Team · 2024· IoT
Discussion of the features

A prepaid RFID parking-card system with integrated IoT environmental monitoring — the most modern stack in the set. An RFID-equipped Wemos (ESP8266) reads parking cards, logs vehicle entry/exit and reports temperature/humidity from a DHT sensor, while a Next.js dashboard manages cards, balances and parking logs and can remotely toggle an LED and a relay. It spans three tiers: PHP endpoints the microcontroller calls, PHP endpoints for a mobile client, and the Next.js management website (backed by Supabase).

  • Prepaid card system — issue an RFID card with a random ID and starting balance, then top-up.
  • Entry/exit billing — parking logs with automatic timestamping and a computed total price.
  • Live sensor telemetry — the device pushes DHT temperature/humidity readings to the backend.
  • Remote actuation — toggle an LED and a switch/relay from the dashboard.
  • Modern management UI — App-Router dashboard with card & log tables (shadcn/ui + TanStack Table) talking to Supabase directly.

Community-Based Reporting & Response System

A community-based reporting and response system with geotagging integration for City Disaster Risk Reduction and Management Offices (CDRRMOs) — piloted with the Biñan City CDRRMO as a replicable model for Philippine LGUs.

Discussion of the features

The system modernizes the incident-reporting and emergency-dispatch workflows of an LGU disaster office — replacing voice-hotline reporting, manual logbooks and verbal radio dispatch with a real-time, cross-platform digital ecosystem. Traditional phone-based reporting produces incomplete situational data, inaccurate locations and delayed response; the command center is fragmented, and field responders lack digital navigation and structured feedback. The system answers each of those with a purpose-built interface, all unified by one Supabase backend using a four-layer architecture (presentation, application, business, data) with PostGIS for geospatial routing.

Citizen Mobile Application React Native · Expo

The public-facing app for submitting structured, geotagged, multimedia incident reports. It enforces a multi-step trust gate before a citizen can report: email/phone verification, then government-ID verification (OCR extraction of name / address / DOB) to prevent fraudulent reports, admin approval, and TOTP-based MFA on login. Reports split into Emergency (immediate dispatch) and Non-Emergency / community issues (forwarded to city departments), auto-attach hardware GPS coordinates and photos/video, and support live tracking of the dispatched responder plus a resolution-confirmation handshake. A directory of local hotlines gives a quick-call fallback.

CDRRMO Admin Web Portal Next.js · Mapbox

The command-center dashboard. Incoming reports appear in real time on a Mapbox map via Supabase WebSocket listeners, separated into emergency and non-emergency queues and categorized (Fire, Medical, Traffic, Police, Weather) with distinct urgency animations. Operators validate reports, assign verified incidents to specific field units (creating the digital link between a report and a responder), watch analytics on incident frequency, geographic distribution and response times, push public broadcast advisories to citizens' phones, and provision authorized responder accounts outside the public sign-up flow.

Responder Mobile Application React Native · Expo

The field app for first responders. A real-time dispatch feed delivers push assignments with full incident context (media, category, citizen details); integrated mapping provides turn-by-turn routing to the exact PostGIS coordinates; and a one-tap status loop (“En Route”, “On Scene”, “Resolved”) instantly updates both the admin portal and the reporting citizen. While en route, the app streams live GPS back to the command center.

Security & data privacy

Built for strict compliance with the Philippine Data Privacy Act of 2012 (RA 10173): AES-256 for PII at rest and SSL/TLS in transit; strict role-based access control via Supabase Row-Level Security across citizen, pending_citizen, responder and operator roles; MFA required for operators and responders; and input validation plus rate limiting to defend against SQL injection and XSS.

Methodology & evaluation

Delivered with Agile Scrum on high-velocity one-week sprints, tracked in GitHub Projects with feature branches merged via peer-reviewed pull requests. Testing was continuous inside each sprint (unit/integration, end-to-end citizen-to-responder simulations, cross-platform and geospatial emulation, load/stress testing, and security scanning), followed by formal usability testing (20 participants, System Usability Scale) and User Acceptance Testing (65 participants running simulated real-world scenarios).
